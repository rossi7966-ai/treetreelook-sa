## 全域 RBAC 角色

角色值域依 DEC-001:`D_OriginUser.Role` 為 SSOT,`D_UserList.Role` 是待清理殘留、描述錯誤不具效力。
可視範圍由 **Role × GID 雙因子**決定(L2 / L3):同一 Role 4,`GID=Null` 為跨案場,`GID` 有值則限該案場。

| 角色 ID | 角色名稱 | 權限範圍 | 對應業務情境 |
|--------|---------|---------|------------|
| R01 | 母帳號(`Role=1`) | 組織最高權限:開通組織、建立各層級帳號、發送邀請信發包、檢視總帳單與訂閱狀態。訂閱平台路徑 B 入口僅本角色可見(L14) | EP01 / EP03 / EP13 |
| R02 | 系統管理員(`Role=2`) | 唯一可新增案場與分區者(L6);帳號啟停與角色指派、系統參數與通知模板設定、任務審核 | EP03 / EP04 / EP05 / EP10 / EP12 |
| R03 | 業主長官(`Role=3`) | 全組織唯讀:檢視全組織的樹與報表,不做任何寫入操作 | EP11 |
| R04 | 廠商負責人(`Role=4`) | 可跨 OID 承包;建立任務、存為範本、指派組長與組員、送審、申請延期。可視範圍受 GID 決定 | EP10 |
| R05 | 廠商組長(`Role=5`) | 建立任務、填寫日誌、召集團隊成員、送審 | EP09 / EP10 |
| R06 | 廠商組員(`Role=6`) | 僅檢視被指派的任務、填寫紀錄與執行意見;**不可建立任務** | EP09 / EP10 |
| R07 | 測量檢驗員(`Role=7`) | 在指派的 GID 內執行測量與調查紀錄;無報表檢視權 | EP09 |
| R08 | 崧旭營運人員(SYS02,`M_AdminList`) | 審核試用申請、管理訂閱用戶與額度 | EP01 / EP14 |
| R09 | 潛在客戶 / 訪客(SYS03,未登入) | 僅公開內容;可送出洽談表單或試用申請 | EP01 / EP15 |

> ⚠️ **R## 為本文件的全域 RBAC 編號**,與 `D_OriginUser.Role` 的數值不等同。R01 ~ R07 對應 SYS01 的 Role 值(括號內註記);R08 走 `M_AdminList` 帳密登入、R09 為未登入訪客,兩者不在 `D_C_Role` 值域內。

## 限制與假設

以下 14 條為素材白紙黑字載明的硬限制,構成本層範疇的邊界約束,下游 AC / AT 不得違反。

| # | 限制 | 出處 |
|---|---|---|
| L1 | 一次僅查一個 OID 的資料,不得跨越 | 系統管理設計v6 p13 |
| L2 | `Role<4` 可看所有資料;`Role>3` 依 GID 決定可視內容(案場、分區、植栽、任務) | 系統管理設計v6 p13 |
| L3 | User 在 OID 內沒有 Group 時,Role 必須 `<4` | 系統管理設計v6 p13 |
| L4 | User 在系統內唯一,但於每個 OID 各持一個 Role;可加入複數個 Group | 系統管理設計v6 p13 |
| L5 | 植栽掛在**分區**,不掛案場 | 系統管理設計v6 p46;`E_ProjectTrees` |
| L6 | 僅系統管理員可新增案場與分區 | 系統管理設計v6 p46 |
| L7 | 試用帳號轉為協力廠商後,不得新增案場 | 系統管理設計v6 p46 |
| L8 | 測量僅能對「植栽類別=1 喬木」填寫,一次一筆 | 測量的新刪修 p3 |
| L9 | 樹高 / 胸高直徑 / 胸高周長 限數字,小數點前三位後兩位;直徑與周長自動互算 | 測量的新刪修 p3 |
| L10 | 測量時間自動帶入「點擊新增測量記錄」的時間;紀錄人自動帶入登入帳號 | 測量的新刪修 p3 |
| L11 | 由任務關聯產生的測量紀錄,不可從植栽端刪除 | xmind 4-1 測量列表 |
| L12 | 試用期限 90 天;試用申請不設人員限制,依申請資訊豐富度人工給額度 | 訂閱相關頁 |
| L13 | 試用申請通過後直接建立 Group,GroupName 取註冊資料,未填則預設「試用群組」 | 系統管理設計v6 |
| L14 | 訂閱平台路徑 B(業務系統跳轉)僅 `Role=1` 可見入口;`Role≠1` 不顯示按鈕 | 訂閱平台v1 p4 |
