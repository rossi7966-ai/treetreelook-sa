## 2. 角色與動機

角色值域依 DEC-001。可視範圍受 `Role` 與 `GID` 雙因子決定——同一 Role 4,`GID=Null` 為跨案場、`GID` 有值則限該案場。

### R1 母帳號(Role 1)
- **任務動機**:開通組織、建立各層級帳號、發送邀請信發包、檢視總帳單與訂閱狀態。
- **心理動機**:握有組織的最終控制權,不希望任何人能繞過自己動組織設定。
- **組織動機**:對外代表組織與崧旭簽約,對內是唯一能決定「誰能進來」的人。
- **現存痛點**:試用與正式為同一 UID 在不同 OID 下的兩個身分,切換工作區的心智負擔高(素材原文:「隨時可以切換回 OID 50 繼續當上帝」)。

### R2 系統管理員(Role 2)
- **任務動機**:新增案場與分區(L6 唯一有權者)、管理帳號啟停與角色指派、設定系統參數與通知模板、審核任務。
- **心理動機**:怕改錯設定影響全組織,需要操作紀錄可回溯。
- **組織動機**:是業主與廠商之間的規則制定者,權責要能被稽核證明。
- **現存痛點**:稽核紀錄(登入登出、操作紀錄)在 DB 完全無表,出事無從追查。

### R3 業主長官(Role 3)
- **任務動機**:檢視全組織的樹與報表,不做任何寫入操作(素材原文:「巡視全境的太上皇」)。
- **心理動機**:要能一眼看到成果,不想學系統操作。
- **組織動機**:對上級或外部呈現 ESG 與固碳成效,需要可直接引用的數據與圖表。
- **現存痛點**:儀錶板尚未開發完成,目前無彙整視圖可用。

### R4 廠商負責人(Role 4)
- **任務動機**:建立任務、存為範本、指派組長與組員、送審、申請延期。
- **心理動機**:承包多個業主(可跨 OID),怕在錯的工作區操作到錯的案場。
- **組織動機**:向業主證明履約進度與工項完成度。
- **現存痛點**:`GID=Null` 與 `GID` 有值的權限落差大,但介面上不易辨識自己當前處於哪一種狀態。

### R5 廠商組長(Role 5)
- **任務動機**:建立任務、填寫日誌、召集團隊成員、送審。
- **心理動機**:現場人力調度以自己為中心,需要快速看到「我的組今天要做什麼」。
- **組織動機**:對負責人回報工班產出。
- **現存痛點**:任務欄位(人 / 事 / 地 / 物 / 時)填寫負擔重,外業以行動裝置操作。

### R6 廠商組員(Role 6)
- **任務動機**:僅檢視被指派的任務、填寫紀錄與執行意見;不可建立任務。
- **心理動機**:只想看到跟自己有關的那幾筆,不要被無關資料淹沒。
- **組織動機**:出工證明。
- **現存痛點**:調查版填報流程若不夠簡,現場會回到紙本。

### R7 測量檢驗員(Role 7)
- **任務動機**:在指派的 GID 內執行測量與調查紀錄(素材原文:「無情的點樹機器」「連看報表的資格都沒有」)。
- **心理動機**:單一重複作業,要求輸入速度與容錯(素材已提出調查版用滑塊輸入的構想)。
- **組織動機**:測量數據品質直接決定固碳量計算的可信度。
- **現存痛點**:樹高常無法直接測量,需樹高轉換輔助(素材已有引導範例)。

### R8 崧旭營運人員(SYS02,`M_AdminList`)
- **任務動機**:審核試用申請、管理訂閱用戶與額度。
- **心理動機**:靠申請資訊豐富度人工判斷給多少額度(L12),需要足夠的申請欄位佐證。
- **組織動機**:試用轉付費的轉換率。
- **現存痛點**:額度機制未實作——素材明載「`D_ContractList` 整張表跳過,等額度機制實作後再補」。

### R9 潛在客戶 / 訪客(SYS03,未登入)
- **任務動機**:理解產品價值、留下聯繫資訊或送出試用申請。
- **心理動機**:懷疑「碳匯數據能不能拿來交差」,需要看到可信示範。
- **組織動機**:ESG 揭露、碳盤查、景觀資產管理的對外舉證。
- **現存痛點**:行動版 PageSpeed 效能 57、LCP 10.5 秒,轉換前就流失。
