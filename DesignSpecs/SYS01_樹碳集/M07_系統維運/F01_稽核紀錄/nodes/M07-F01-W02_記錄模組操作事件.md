## 🟨1. 故事背景(Story)
- **As a** 系統管理員(Role 2)
- **I want** 系統自動記下各模組每一次新增、修改、刪除
- **So that** 資料或權限被改動時能追到是誰、在何時、對什麼做了什麼動作

## 🟦2. 業務規則(Rules)
- **Rule 1**:記錄範圍為植栽管理、場域管理、任務管理、帳號管理(含廠商群組)之新增(C)、修改(U)、刪除(D);查詢(R)不記。各模組應記的動作依 `[!TBD-W02-05]` 清單。
  > 🔗 **相依性宣告**:DEC-015、DEC-022。來源 F:M01-F02 / M01-F03 / M02 各 F / M03 各 F / M05 各 F `[!CROSS-LINK → M01-F02-W##]` 等,目標節點未建,暫指 [M07-F01-W99](./M07-F01-W99_OutOfScope.md)。
- **Rule 2**:每筆記錄時間(至秒)、當前 OID、UID、姓名、當下 Role、模組、功能、動作、操作對象(識別碼 + 名稱)、摘要、真實來源 IP、反向代理 IP、裝置。
  > 🔗 **相依性宣告**:[W01](./M07-F01-W01_記錄進出組織事件.md) Rule 4。
- **Rule 3**:只記動作,不記資料歷程——不記修改前後值、新增後資料、刪除前快照。
  > 🔗 **相依性宣告**:DEC-022。
- **Rule 4**:屬改變資料範圍的動作(修改角色、修改廠商群組 GID、異動廠商群組成員)標記「權限異動」。
  > 🔗 **相依性宣告**:DEC-011 資料範圍層、DEC-022。
- **Rule 5**:查詢、檢視詳情、匯出稽核紀錄本身不記。
  > 🔗 **相依性宣告**:DEC-022。
- **Rule 6**:紀錄寫入失敗時,原業務操作照常完成;失敗不另記稽核,當一般錯誤 LOG 處理。
  > 🔗 **相依性宣告**:DEC-022。
- **Rule 7**:紀錄唯讀,保存至少 2 年,目前不做清除或封存。
  > 🔗 **相依性宣告**:DEC-015、DEC-022。

## 🟩3. 具體實例與測試資料(Examples / BDD Scenarios)
### Scenario:[正常路徑] 調整帳號的角色與廠商群組
- **Given** tpark3 為 OID 1 的系統管理員
- **When** 於帳號管理調整 test_team_leader 的角色與廠商群組後儲存
- **Then** OID 1 新增一筆操作紀錄:模組=帳號管理、功能=帳號、動作=修改、對象=test_team_leader,並標記權限異動
- **And** 紀錄不含角色與廠商群組的修改前後值

### Scenario:[正常路徑] 修改測量值
- **Given** survey1 在 OID 1 內
- **When** 修改植栽 T-000812 樟樹的胸高直徑 DBH 後儲存
- **Then** 新增一筆模組=植栽管理、功能=測量紀錄、動作=修改、對象=T-000812 樟樹
- **And** 紀錄不含 DBH 的修改前後值

### Scenario:[正常路徑] 刪除分區
- **When** 系統管理員刪除分區「大安森林公園 / 臨時分區」
- **Then** 新增一筆動作=刪除、對象=大安森林公園 / 臨時分區,不含刪除前快照

### Scenario:[邊界] 查詢不記
- **When** 系統管理員在植栽列表按[查詢],或在操作紀錄頁按[查詢]
- **Then** 不新增任何操作紀錄

### Scenario:[異常] 紀錄寫入失敗
- **Given** 紀錄寫入失敗
- **When** survey1 儲存測量值修改
- **Then** 測量值照常儲存成功,不新增操作紀錄
- **And** 錯誤寫入系統錯誤 LOG
