# 專案策略層(L5)

## 專案目標

以「組織 OID → 案場 `E_LocationList` → 分區 `E_ProjectList` → 植栽 `F_TreeList`」的歸屬鏈(DEC-005),將景觀與綠地植栽納管為可追溯的資產;累積維養、測量、健康三類歷程,並由測量數據換算固碳量,供 ESG 揭露、碳盤查與景觀資產管理對外舉證。

對外以官網取得潛在客戶留資,經訂閱平台完成試用審核與付費開通,形成「獲客 → 試用 → 付費 → 使用」的商業閉環。

**分析基準**:依 DEC-007,現行系統**已上線**,本次系統分析為**純 to-be**。as-is 修正(2025Tpark 初驗缺失:學名斜體、通知信帶系統名)已於素材端完成,不納入本次範圍。功能存在「已實作 / 未實作 / 未知」三態,判定依據待 E4 取回。

## 利害關係人

| 角色 | 關注點 | 影響度 |
|------|-------|--------|
| R1 母帳號(Role 1) | 握有組織最終控制權,不希望任何人繞過自己動組織設定;對外代表組織與崧旭簽約,對內是唯一能決定「誰能進來」的人 | 高 |
| R2 系統管理員(Role 2) | 是業主與廠商之間的規則制定者,權責要能被稽核證明;怕改錯設定影響全組織 | 高 |
| R3 業主長官(Role 3) | 對上級或外部呈現 ESG 與固碳成效,需要可直接引用的數據與圖表;要一眼看到成果,不想學系統操作 | 高 |
| R4 廠商負責人(Role 4) | 向業主證明履約進度與工項完成度;承包多個業主(可跨 OID),怕在錯的工作區操作到錯的案場 | 高 |
| R5 廠商組長(Role 5) | 對負責人回報工班產出;現場人力調度以自己為中心,需快速看到「我的組今天要做什麼」 | 中 |
| R6 廠商組員(Role 6) | 出工證明;只想看到跟自己有關的那幾筆,不要被無關資料淹沒 | 中 |
| R7 測量檢驗員(Role 7) | 測量數據品質直接決定固碳量計算的可信度;單一重複作業,要求輸入速度與容錯 | 高 |
| R8 崧旭營運人員(SYS02) | 試用轉付費的轉換率;靠申請資訊豐富度人工判斷給多少額度(L12) | 高 |
| R9 潛在客戶 / 訪客(SYS03) | ESG 揭露、碳盤查、景觀資產管理的對外舉證;懷疑「碳匯數據能不能拿來交差」,需要看到可信示範 | 中 |

> 角色的完整任務動機、心理動機與現存痛點見 `06_HandoffPackage.md` §2;權限範圍與對應業務情境見 `02_Scope.md`「全域 RBAC 角色」。
>
> ⚠️ **影響度欄為 Runner 依 §2 動機強度初判,待 SA 確認**。

## 業務驅動因素

| # | 驅動因素 | 依據 |
|---|---|---|
| D1 | **稽核斷點** —— 登入登出紀錄與操作紀錄在 DB 完全無表,出事無從追查,系統管理員的權責無法被稽核證明 | `05_SourceAudit.md` G07;`06` §2 R2 現存痛點 |
| D2 | **成效無彙整視圖** —— 碳匯儀錶板尚未開發完成,業主長官目前無可直接引用的數據與圖表 | DEC-008;`06` §2 R3 現存痛點 |
| D3 | **維養歷程無載體** —— 維養紀錄尚未實作,6 大類 13 項工法的歷程無處可落,植栽歷程鏈缺一環 | DEC-004;`05_SourceAudit.md` G01 |
| D4 | **跨組織誤操作風險** —— 同一 UID 在每個 OID 各持一個 Role(L4),試用與正式為不同 OID 下的兩個身分,切換工作區心智負擔高 | L4;`06` §2 R1 現存痛點 |
| D5 | **權限狀態不可辨識** —— Role 4 在 `GID=Null` 與 `GID` 有值之間權限落差大,但介面上不易辨識自己當前處於哪一種狀態 | L2;`06` §2 R4 現存痛點 |
| D6 | **外業回退紙本風險** —— 調查版填報流程若不夠簡,現場會回到紙本;任務欄位(人 / 事 / 地 / 物 / 時)填寫負擔重 | `06` §2 R5 / R6 現存痛點 |
| D7 | **獲客前端流失** —— 官網行動版 PageSpeed 效能 57、LCP 10.5 秒,潛在客戶在轉換前就流失 | `Landing Page調整.pptx`;`06` §2 R9 現存痛點 |
| D8 | **商業機制未落地** —— 授權額度(帳號 / 場域 / 植栽上限)機制未實作,素材明載「`D_ContractList` 整張表跳過,等額度機制實作後再補」 | E9;`06` §2 R8 現存痛點 |
