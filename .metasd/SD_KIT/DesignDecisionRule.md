# DesignDecisionRule(決策卡集)

> 白話:SD會反覆遇到的多解決策,預先給答案跟改道條件——常態零決策、特徵觸發改道、真難題到人面前時已是選擇題。

## 卡片格式(六欄)

`DP-ID/決策點/預設解/偏離觸發特徵(盡量可機判)/替代解+代價聲明/升級條件(何時請示拍板者)`

運轉律:①無特徵→照預設走,不記錄②命中觸發特徵→改道+登ADR(`.issues/I-SD-###/ADR-N.md`體例,附特徵證據)③升級條件命中→產請示卡(選項+後果,禁開放題)④同卡ADR累積N=3→觸發預設值複審。

## 已定稿卡

### DP-SD-001 系統邊界判定(開案第一張卡)

| 欄 | 內容 |
|----|------|
| 預設解 | 開案先判本次工作範圍屬「既有系統擴建」或「新系統」,結果寫入專案慣例檔(`00_ProjectConvention.md`)檔頭。擴建→風格層延續既有慣例(慣例檔逐條抄現行做法+附依據);新系統→家規預設值 |
| 偏離觸發特徵 | 傾向「新系統」:獨立DB實例、獨立服務與網域、獨立使用者群與驗證體系。傾向「擴建」:同庫、同服務、同中介層、同一群消費者 |
| 替代解+代價 | 擴建卻採新規矩=同一系統養兩代規矩,跨代查詢與維護永久付費;新系統卻硬套舊規矩=把舊系統的歷史債複製進新系統 |
| 升級條件 | 特徵混合(如同庫不同服務)或團隊意見分歧→請示卡附兩案後果;判定結果要變更=重大變更,重新拍板並盤點已產出物 |

### DP-DB-001 正規化程度

| 欄 | 內容 |
|----|------|
| 預設解 | 3NF |
| 偏離觸發特徵 | 讀寫比懸殊(讀≫寫)/報表聚合高頻/join深度>3/欄位變更頻率低 |
| 替代解+代價 | 反正規化寬表/彙總表=字典標`derived: true`+再生規則(來源表+聚合邏輯);代價:寫入必經再生、禁直寫(R-DB-P03) |
| 升級條件 | 特徵資料缺失或互相衝突→請示卡附兩案後果 |

### DP-API-001 查詢動詞

| 欄 | 內容 |
|----|------|
| 預設解 | 查詢用`GET`+query參數 |
| 偏離觸發特徵 | 查詢條件為結構化物件(如座標陣列extent)/參數可能超URL安全長度/敏感值不宜入URL |
| 替代解+代價 | `POST /{resources}/search`專用端點+body;代價:失去HTTP快取與書籤性;OAS標`x-query-semantics: read` |
| 升級條件 | 同資源兩式並存需求→請示 |

案例錨:農氣station/all以POST承載結構化extent屬正當偏離;扁平條件POST屬不正當(C表§三)。

### DP-DB-002 uuid啟用時機

| 欄 | 內容 |
|----|------|
| 預設解 | 不建`uuid`欄。僅「主案件/主業務資料表」且會因URL/API查詢、外部連結或安全性隔離而**外顯**時加入 |
| 偏離觸發特徵 | 代碼表/關聯表/日誌表/同步暫存表出現uuid=違反預設,需說明;主業務表無任何外顯面卻加uuid=同上 |
| 替代解+代價 | 全表一律加uuid:索引與儲存成本+假安全感;全不加:外顯場景只能曝露sid流水號(可被枚舉猜測),資安代價更高 |
| 升級條件 | 表的「會不會外顯」判斷不了→請示卡附使用場景 |

### DP-DB-005 狀態欄型別與起值

| 欄 | 內容 |
|----|------|
| 預設解 | 狀態/分類欄(`type`/`class`/`status`)用`int`,數值**從1開始**;語意一律掛`CODE_`表對照,對外API依三層對映轉string代碼(R-API-C02/EN02),int不直曝 |
| 偏離觸發特徵 | 代碼值需跨系統穩定識別或直接對外交換(如政府代碼、跨機關介接)→改string代碼直存/屬既有系統擴建且同名欄既有實作不同(DP-SD-001+慣例檔) |
| 替代解+代價 | string代碼直存:可讀性高、免翻譯,但索引較寬、打錯字風險入庫;int序數:窄索引,但語意在對照表外,報表與除錯多一次翻譯。**起值鐵則:全案統一從1,0保留給「未設定」語意,混用即陷阱** |
| 升級條件 | 同一表內新舊兩制並存需求→請示卡附兩案後果 |
