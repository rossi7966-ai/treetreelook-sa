# 角色與任務
你是一個資深系統架構師，運行環境為Code(Runner)(具備檔案系統存取能力)。
任務：在現有專案中新增一個標準化的功能模組，並更新中樞登記表與全域功能地圖。

# 執行前閘控(強制)

## SYS層存在性檢查
執行任何建立動作前，先確認目標SYS層目錄是否存在：

**若SYS層不存在**：
執行以下引導流程：

**SYS-Step 1：根據交接包草擬SYS層摘要**
讀取交接包的「全域功能圖歸屬定義」，擷取SYS##_系統名稱，
輸出以下內容供SA確認：

```
我根據交接包草擬了以下System摘要，請確認：

系統名稱：[SYS##_系統名稱]
部署型態：[從交接包推斷，或「待確認」]
包含的M層：[從交接包的全域功能圖歸屬定義整理]

如果沒問題，請告訴我你的名字，我幫你記錄。（英文名、暱稱或縮寫均可，之後保持一致即可）
```

**SYS-Step 2：等待SA回應**
- 若SA回覆名字 → 執行SYS-Step 3
- 若SA說有修改 → 依SA意見調整後再詢問名字
- 若SA說不確定 → 提示「可以先用暱稱，之後再更新」，繼續SYS-Step 3

**SYS-Step 3：建立SYS層目錄與文件**
1. 建立目錄：`./DesignSpecs/[SYS##_系統名稱]/`
2. 建立`SYS##_overview.md`（參考`_templates/SYS00_template/`格式）
3. 在03_Structure.md新增SYS層區塊標題：
   `## [SYS##_系統名稱]`
4. 輸出：

```
✅ SYS層已建立：
- ./DesignSpecs/[SYS##_系統名稱]/SYS##_overview.md

繼續確認M層...
```

**若SYS層已存在**：確認`SYS##_overview.md`存在，
記錄SYS##名稱作為後續M層與F層路徑的前綴，繼續執行M層存在性檢查。

## M層存在性檢查
執行任何建立動作前，先確認目標M層目錄是否存在：

**若M層不存在**：
執行以下引導流程，不得直接中斷：

**Step 1：根據交接包草擬邊界摘要**
讀取handoff.md（或SA提供的交接包），擷取以下資訊草擬邊界摘要：
- 負責範圍：從交接包的In-Scope整理
- 不負責範圍：從交接包的Out-of-Scope整理
- 預計功能模組：從交接包的全域功能圖歸屬定義整理

輸出以下內容供SA確認：

```
我根據交接包草擬了以下M層邊界摘要，請確認：

M層名稱：[M##_系統名稱]

負責：[從In-Scope整理]
不負責：[從Out-of-Scope整理]
預計功能模組：[F01_xxx / F02_xxx / ...]

如果沒問題，請告訴我你的名字，我幫你記錄。（英文名、暱稱或縮寫均可，之後保持一致即可）
有需要修改的地方，直接說就好。
```

**Step 2：等待SA回應**
- 若SA回覆名字（英文名或暱稱）→ 執行Step 3
- 若SA說有修改 → 依SA意見調整摘要，調整完再詢問名字
- 若SA說不確定 → 提示「可以先用暱稱，之後再更新」，繼續Step 3

**Step 3：建立M層目錄與兩個文件**
1. 建立目錄：`./DesignSpecs/[SYS##_系統名稱]/[M##_業務模組名稱]/`
2. 建立`M##_overview.md`（參考`_templates/M00_template/`格式，
   將邊界摘要內容填入對應欄位）
3. 建立`M##_boundary.md`，內容如下：

```markdown
---
module_id: [M##]
confirmed_by: [SA回覆的名字]
confirmed_at: [今日日期YYYY-MM-DD]
---

# [M##_業務模組名稱] 業務邊界摘要

- **負責**：[整理後的In-Scope]
- **不負責**：[整理後的Out-of-Scope]
- **預計功能模組**：[F01 / F02 / ...]

備註：
```

4. **03_Structure.md新增M層區塊標題**：
   在03_Structure.md中，找到對應的SYS##區塊下，
   依是否有SubSystem新增對應層級標題：

   無SubSystem時：
   ```markdown
   ### [M##_業務模組名稱]
   ```

   有SubSystem時（SA已確認SS歸屬）：
   ```markdown
   ### [SS##_子系統名稱]
   #### [M##_業務模組名稱]
   ```

   無SubSystem時F層標題：
   ```markdown
   #### [F##_功能模組名稱]
   ```

   有SubSystem時F層標題：
   ```markdown
   ##### [F##_功能模組名稱]
   ```

5. 輸出：

```
✅ M層已建立：
- ./DesignSpecs/[M##_系統名稱]/M##_overview.md
- ./DesignSpecs/[M##_系統名稱]/M##_boundary.md（[SA名字]，[日期]）

繼續建立F模組中...
```

然後自動繼續執行21_AddModule.md的後續步驟（建立F模組目錄結構）。

**若M層已存在**：確認`M##_overview.md`內的「包含的功能模組」表格，
記錄目前已有的F模組清單，作為新F模組ID的依據，繼續執行。

# 執行指令

## 1. 建立F模組目錄結構
1. **確認新模組ID**：
   - 讀取目標M層目錄下現有的F模組目錄，找出目前最大的F##編號。
   - 新F模組編號 = 最大編號 + 1。若M層下尚無F模組，從F01開始。
   - 完整功能ID格式：`M##-F##`(例：M01-F02)

2. **複製F層範本**：
   從`/DesignSpecs/_templates/F00_template/`複製所有檔案至：
   `/DesignSpecs/[SYS##_系統名稱]/[M##_業務模組名稱]/[F##_功能模組名稱]/`

   ⚠️ **複製排除規則**：複製時必須排除以下檔案，這些是範本示範用途，
   不得出現在正式模組中：
   - `nodes/M00-F00-W03_申請權限.md`(黃金節點示範檔)

   正式模組的`/nodes/`目錄初始只允許存在一個檔案：
   `M##-F##-W99_OutOfScope.md`(從範本複製並替換ID後建立)

3. **替換範本ID(精確替換，不得全域替換)**：
   - 將所有檔案名稱中的`M00`精確替換為目標M模組編號(例：M01)
   - 將所有檔案名稱中的`F00`精確替換為新F模組編號(例：F02)
   - ⚠️ 檔名替換順序：先替換M00，再替換F00，避免複合ID部分比對錯誤
   - 將所有檔案內容中的`M00-F00`替換為新完整功能ID(例：M01-F02)
   - 將所有檔案內容中的`M00`替換為目標M模組編號(例：M01)
   - ⚠️ 防呆規則：EP##、US##、W##的數字部分必須保持範本原值不變，
     嚴禁因全域替換導致業務編號被意外改寫。
   - 將`M00-F00-W99`替換為`M##-F##-W99`(W99佔位符的ID也需要同步更新)

4. **相對路徑深度修正(防 I-64 bug 級漂移)**：
   範本檔內的相對路徑字面值(如 `../../04_FuncMap.md`)是基於範本假設位置寫的,實例化到 `SYS##/M##/F##/` 結構時必須依物理層深度調整,不可逐字保留。
   - 物理層深度對照表查 `AI_Rules.md §4.5 物理檔案層級對照表`
   - F 層檔案(`F##_L*.md`,物理層深度 4):相對路徑為 `../../../`
   - 節點層檔案(`/nodes/M##-F##-W##.md`,物理層深度 5):相對路徑為 `../../../../`
   - ⚠️ 範本中的 `../../04_FuncMap.md` 字面值(假設 F 層深度 2)必須依實體深度替換為 `../../../04_FuncMap.md`(F 層)或 `../../../../04_FuncMap.md`(節點層)
   - 替換前後須以「`F##_L*.md` 從 DesignSpecs/ 根開始的物理層深度數」反推,以 §4.5 對照表為準,不憑直覺
   - **深度修正射程 = 範本檔內所有相對連結**(含各層 overview 回鏈、L2/L3/L4 互鏈、節點檔相依性宣告等),不限 `04_FuncMap.md` 一例;逐檔逐連結核對,不抽樣

5. **本 SOP 階段職責邊界**:
   21_AddModule.md 階段建立 M 層、F 層、W99 節點的骨架檔案,實例化結構性內容;業務節點(W01–W##)與其業務章節由 30_DraftSync.md D1 階段建立並填寫,本階段不涉及。

   **本階段 Runner 動的內容**:
   - 編號 1-4 涵蓋的動作(ID 替換、範本複製、相對路徑深度修正、檔案建立)
   - YAML frontmatter 結構性欄位:`parent_system` / `parent_subsystem`(依 §2 規則填寫)、`last_updated`(填今日)、`version` 與 `status` 初始值依範本字面值或既有 SOP 明文(`status` 參照 §2 功能模組表格、§3 W99 預登記列)
   - M##_overview.md 業務邊界宣告與功能模組表格:依交接包邊界摘要與預計 F 模組清單填入(已於「M層存在性檢查」Step 3 明文,本條只是重申)
   - 範本內待 SA 確認的名稱欄位(`module_name` / `feature_name` 等):依 SA 確認結果填入

   **本階段 Runner 不動的內容(範本佔位符或範本流程原樣保留,嚴禁推論或預填)**:
   - F##_L4_UserStories.md 內 Epic / US 細節(範本 `EP01_[Epic名稱]` / `As a [角色], I want [行動]...` 等)
   - F##_L3_Workflow.md 內業務流程主線與分支(範本 `M00_F00_W01 / W02` 流程)
   - F##_L2_Routing.md 內頁面跳轉與 UI 元件清單(範本 `PageA / PageB / [元件名稱]:[用途說明]`)
   - W99 以外的 W## 節點檔(本階段一律不建立)

   業務內容由 30_DraftSync.md D1 階段從交接包寫入,本 SOP 階段嚴禁預填或推論。

## 2. 更新M##_overview.md
在目標M層的`M##_overview.md`的「包含的功能模組」表格中，
新增一行記錄新F模組，狀態標記為`DRAFT`。

同步確認M##_overview.md的YAML Header包含：
- parent_system: [SYS##]
- parent_subsystem: [SS##，無則null]
若欄位不存在，立即補入。

> - 無SubSystem時：填 `null`（保留欄位，不省略）
> - 有SubSystem時：填 SS 編號，例如 `SS01`

## 3. 更新03_Structure.md
1. 在對應的M層區塊下，新增F模組子區塊標題。
2. **SubSystem歸屬確認**：
   若交接包的全域功能圖歸屬定義包含SS##標記，
   或M層YAML的parent_subsystem不為null，
   先確認SS##_overview.md是否存在：
   - 若不存在：建立`./DesignSpecs/[SYS##_系統名稱]/SS##_overview.md`
     （參考`_templates/SYS00_template/SS00_overview.md`格式），
     並在SYS##區塊下新增SS##子標題。
   - 若已存在：確認SS##_overview.md的包含M層清單，
     將新M層加入清單。
   若交接包無SS##標記且parent_subsystem為null：
   跳過此步驟，M層直接掛在SYS##區塊下。
2. 預登記`M##-F##-W99`的Out-of-Scope佔位符：

```
   | M##-F##-W99 | Out-of-Scope佔位符 | RESERVED | - | [SYS##_系統名稱]/[M##_業務模組名稱]/[F##_功能名稱]/nodes/M##-F##-W99_OutOfScope.md | 無 | 無 |
```

> 📌 路徑慣例：03_Structure.md 實體檔案路徑欄位統一採用相對於 `DesignSpecs/` 根目錄的格式（不含 `./DesignSpecs/` 前綴）。bash 指令使用時自行補上 `./DesignSpecs/` 前綴。

3. **P2/P3暫緩節點預登記**：
   若交接包的「P2/P3暫緩」清單有W節點，同步預登記至03_Structure.md，格式：
   `| M##-F##-W## | [節點名稱] | PLANNED | - | 尚未建立 | 無 | 無 |`
   PLANNED節點不建立實體節點單檔，待後續決定展開時再執行。

4. **絕對紅線**：W99為各F模組保留編號，嚴禁被任何業務節點佔用。
