# ⟪任務代號⟫ 派工單

> 本單=執行者的**唯一任務來源**,不另給口頭補充;疑義走停止條件記帳提問,不腦補。
> 卡點與缺口照實記錄=工作的一部分,不是扣分項(附錄A)。

## 〇、生效條件

1. ⟪前置驗收/裁示⟫
2. ⟪工具前提;不可用=不啟動⟫
3. 生效=本檔 status 轉 ACTIVE(拍板者或其授權的主 Runner)。

## 一、目標(交付定義;完成=全數交付+機器閘門綠)

| # | 交付 | 說明 |
|---|------|------|
| 1 | ⟪…⟫ | ⟪…⟫ |

交付順序照表;**每項=一批次**,批次完成即留證據(§六)+commit(§七)再進下一項。

## 二、授權範圍與禁區

- 可寫:⟪白名單,精確到頁/目錄⟫
- 禁改:⟪SA 檔/生成物/規則層/既有報告 等⟫
- 排他:本單執行期間該 repo 單一 session;主 Runner 不併行,以 commit 為界。

## 三、規則進入點(冷啟動;依序讀)

1. ⟪00_START_UI 三件⟫
2. ⟪AI_Rules 總紀律⟫
3. ⟪任務相關 SOP+前輪實務註記(必讀)⟫

## 四、機器閘門自證(每批次收批前;貼命令輸出入證據)

```
⟪run_checks/專用 diff 等命令,參數以實際 CLI 驗過⟫
```

- 自證原則:**宣稱=命令輸出**,不得以「看起來正確」收批。
- **內容抽比**(必做;外稽 A2 教訓=只驗「建了」沒驗「值對」):每批次抽 ≥2 個
  產出物,逐字比對權威來源(SSOT 原文/tokens 值/規格值),對照結果入證據。
- 「要不要跑某檢核」**不由執行者自判**——本單 §四 列了就跑,沒列的不跑;
  覺得該跑而沒列=停止條件提問。

## 五、停止條件(觸發=停該筆+記附錄A+回報;不得自行擴權)

1. 規則缺席/衝突/找不到。
2. 授權邊界不明。
3. 技術錯誤同批重試 2 次仍失敗;自證 diff 無法自修收斂。
4. 發現上游疑義(登帳不改源)。

## 六、證據要求(evidence/⟪R##⟫/;批次為單位)

- 每批:⟪截圖/讀回檔/命令輸出⟫,命名 `批次#_項目.*`,報告證據表列帳。

## 七、版控檢查點(**必要條件**;外稽 B3=UIX-016 修正)

- **每批次收批=一筆 commit**(atomic;前綴=⟪repo 慣例⟫;禁 push 除非明示)。
- 完成訊號**必含各批次 commit hash**——零 commit=交付不完整,驗收不受理。

## 八、回報格式

- 完工報告:起草 `⟪reviews/R##_名.md⟫`(派工契約/逐批結果/實務註記新增/議題與回補/
  證據表/附錄A),標注「執行者自報,待驗收覆核」;驗收端補覆核節後定稿。
- 附錄A 逐批**即時填**,不得事後回憶補填。

## 附錄A、觀測指標(制度計量;定義精化=外稽 B3)

| 指標 | 定義 | 記錄 |
|------|------|------|
| 卡點提問數 | 觸發 §五 次數 | 逐筆:批次#/觸發條/原因分類=規則缺席/衝突/找不到/授權不明/技術障礙 |
| V 首跑 fail | 每批 §四 命令首跑 fail 數 | 逐批 |
| **自修輪數** | 每批「錯誤→修復→重驗」迭代數,**含技術障礙修復**(障礙修好=一輪自修) | 逐批 |
| R 快掃補抓 | 驗收端抓到而自證未抓的問題數 | 驗收端填 |
| 違紀數 | 白名單外寫入/手改生成物/跳批/缺 commit/缺證據 | 驗收端稽,期望=0 |

## 附錄B、驗收程序(主 Runner;供執行者預知標準)

1. §四 命令全套獨立重跑(不信自報,重取證)。
2. 內容抽比獨立重做(換一組樣本)。
3. **指標反推覆核**:以證據與 commit 序反推附錄A 自報值,不一致=更正記錄(非懲罰,入觀測)。
4. 缺口逐筆入 50_IssueFlow 成長迴路;報告補驗收節定稿→00_Status 更新→交拍板者。
