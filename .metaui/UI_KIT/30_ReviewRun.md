# 30|審查執行(G1-R / G2-R)

> 白話:機器先把可判定的事查完(V 段)，人和 AI 只看「需要眼睛和判斷」的部分。
> 審查對象是**渲染截圖**，不是原始碼——原始碼的問題屬 V 層管轄。

## 輸入(E-1)

- 頁面**渲染截圖**(瀏覽器開啟 `ui/pages/*.html` 所截;五態都要，缺態標 ⚠️ 未提供)
- 對應閘門的 V 段 stdout(run_checks 已跑完)
- `ui/10_UIFlow.md`(主軸宣告與登記表)
- `ui/00_FlowMap.html`(頁面串接綜覽+宣告×實掃雙源對照;G1-R 與 Prototype-R 固定輸入)
- G2 另需:`UIFoundation/00_TokenSheet.md`(比對基準的人讀版)
- Prototype-R 另需:proto 渲染截圖(單態)+`ui/00_CopySheet.md` AI-R 佇列

原始碼不作為 R 層審查輸入;若只拿到原始碼，先渲染截圖再審。

## 審查前禁令(承 ui-review skill，繼續有效)

1. **禁數值估算**:不得目測輸出任何 px / 比例 / 色碼判斷——數值歸 V 層(UIV-05/06)
2. **禁無障礙推論**:無障礙屬拆面 out(政府檢測工具軌)，任何情況不審不列
3. 僅單態截圖時，其餘狀態標「⚠️ 未提供截圖，無法確認」，不推測
4. **警惕審美-可用性效應**:styled 截圖「看起來完成」不等於結構正確，G1 未過不得因美觀放行(wire 無樣式先審結構、G2 才上色，即此偏誤的結構性防護)

## G1-R 清單(結構定案審查)

### 1. 主軸實現(v0.3 核心)

- 登記表宣告的 primary action 是否為該態**視覺最重**的行動?
- 次要行動是否搶焦(同色、同重、位置更顯眼)?
- 非主軸導覽範式(如功能選單區)是否視覺從屬於主軸?
> UIV-08 只驗「唯一性」,「視覺強弱是否如宣告」是這裡的判斷責任。

### 2. 視覺層級與版面

依 `references/visual-hierarchy.md`:CRAP(對比/重複/對齊/親密)、Gestalt、
視線動線(F/Z-Pattern 落點)、White Space、Typographic Scale(僅視覺感知層，字級數值歸 V)。

### 3. 易用性原則六條・結構子集(對 flow + 截圖序列)

| 原則 | 檢什麼 | 對應 10_Principles |
|--------|--------|-------------------|
| 系統狀態可見性 | 五態是否讓使用者知道「現在怎麼了」 | #3 回饋 |
| 真實世界匹配 | 文案術語 ↔ 00_Glossary / 領域慣用語(模糊層;精確比對歸 UIV-04) | #9 遵循慣例 |
| 使用者控制與自由 | 取消 / 返回 / 逃生路徑存在且可見 | #6 可逆性 |
| 錯誤預防與復原 | error 態有明確訊息與復原引導 | #5 錯誤預防 |
| 一致性 | 同功能元件跨頁視覺與行為一致 | #1 一致性 |
| 辨識優於回憶 | 導覽自我說明，不要求使用者記住上一頁 | #8 資訊分組/#9 遵循慣例 |

原則單源=`UIFoundation/10_Principles.md`(含閘門地圖);本表為執行視角映射，不另立原則清單。

### 4. UI Stack 覆蓋表

Blank / Loading / Partial / Error / Ideal 逐態記 ✅ / ❌ / ⚠️ 未提供(表格式沿報告範本)。

## G2-R 清單(樣式合規殘餘)

數值合規已由 UIV-05/06 機器判定;R 層只剩:

- 元件風格跨頁一致性(需多頁截圖對照，單頁不下結論)
- token 語意誤用(值對但語意錯，如警示色拿去當品牌色)
- **原則覆驗**:依 10_Principles 閘門地圖 G2-R 欄，對渲染截圖逐條記過/不過——
  #1 跨頁視覺一致、#7 目標要大要近(大小/距離感知)、#9 遵循慣例(慣例感知)
- 文案判讀:讀 `ui/00_CopySheet.md` AI-R 佇列逐條過(30_UXWriting §十)
- **拍板者抽比**(外稽 20260712 A4 甲案):報告的佇列判讀節固定抽 3 條(不足全抽)，
  由拍板者於驗收時覆判;抽中翻案率記入報告觀測欄——判讀品質的第二道網，
  翻案率累積偏高再升級判讀雙席(乙案)
- **全譜易用性覆核**:G2 首輪、通盤檢討輪、重大變更後，依下節 Nielsen 十大易用性原則逐項執行;
  小變更維持「變更後覆驗」三條快掃

🔴🟡 入議題帳。裁決單源=10_Principles(本表=評估視角映射，不另立原則);無障礙不審(拆面紀律)。

## Prototype-R 清單(產品視圖審查;45_PrototypeView)

時機=prototype 產出後、驗收輪必跑。禁令同前(禁數值估算/禁無障礙推論)。
判斷對象是「這個視圖能不能拿去見人」，不重審結構與樣式合規(那是 G1/G2 已付訖的帳)。

1. **第一畫面(Hero Section)吸引力**:hero 是否 30 秒內傳達「這是什麼、對我有什麼用、下一步做什麼」;
   display 層級是否成立(視覺重量序=價值序，非工具階)
2. **探索潛力**:分段帶節奏是否引導下滑;卡片與連結可供性(看起來可點)是否明確;
   回訪捷徑是否直達
3. **品牌與 DS 同源**:chrome 與內容同一 token 家族;讓色紀律維持(警戒色不挪用)
4. **文案完稿判讀**:AI-R 佇列逐條過(30_UXWriting §十);假設代決文案讀起來是否自然
   (不露佔位腔);完稿門檻(45 規則 5)未過→HOLD
5. **同構抽查**:抽至少 2 頁對照審查視圖——資訊節點與連結拓樸無增刪
   (結構漂移=回 G1，不得在 proto 層私改)
6. **FlowMap 對照**:雙源差異表逐筆處置(宣告未實作→補頁或修 flow;實掃未宣告→
   補宣告或刪連結)，殘留差異須附理由

產出併當輪 R 報告(gate_result 含 prototype 判定);🔴🟡 入議題帳。

## 變更後覆驗

ui/ 任何影響渲染結果的變更(結構/樣式/文案)落地後:

1. 重跑對應閘門 V 子集(必要)
2. 對受影響頁面的渲染結果快掃閘門地圖 G2-R 欄三條，結果記於當輪報告或議題帳備註
3. 僅文案微調(🟢 級)得以「V 重跑+00_CopySheet 差異檢視」代替截圖快掃

## 產出

1. 報告 `ui/reviews/R##_G#.md`(templates/R00_Review_template.md):
   - V 段:貼 run_checks **真實 stdout 原文**
   - R 段:發現表(UIX 候選|嚴重度 🔴🟡🟢⚪|面向|位置|描述→建議|**可攔截閘門**)
   - 範圍外轉介:偶遇 out 面向問題記一行(現象+去處)，不展開
2. `gate_result` 判定:**V 全綠 + R 無未結 🔴 → PASS**，否則 HOLD
3. 議題同步:🔴🟡 逐條入 `UIFoundation/90_IssueLedger.md`(流程見 50_IssueFlow;UIV-07 會驗同步)
