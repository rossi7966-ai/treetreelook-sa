# 50|設計議題生命週期

> 白話:所有設計問題只有一本帳(90_IssueLedger.md)。報告是「當時看到什麼」
> 的不可變紀錄,永不回改;「修了沒」只看帳。

## 四態

| 狀態 | 進入條件 | 誰動 |
|------|---------|------|
| 識別 | 報告 R 段 🔴🟡 發現,ledger 配發 UIX-###(專案內流水,終身不改) | AI 登錄 |
| 排序 | 拍板者依嚴重度 × 修復成本定序 | 拍板者 |
| 處理 | 修 artifact,ledger 記處理 commit | AI 執行 |
| 結案 | **下一輪對應閘門 V 重跑通過或 R 覆核確認**——不自證 | AI 提請,拍板者可抽查 |

## 議題帳(`UIFoundation/90_IssueLedger.md`)

欄位:UIX-### | 狀態 | 嚴重度 | 歸屬(F##/P##/全域)| 來源報告 | 可攔截閘門 | 處理 commit | 備註
同步紀律:報告 🔴🟡 ↔ ledger 行雙向對應,UIV-07 機器驗;🟢 小優化可不入帳(報告留痕即可)。

## 門檻(數據驅動,值屬 Candidate 待實戰校準)

- **G0-R 撤銷**:連續兩個專案,G0-R(判斷段)可攔截占比 < 20% → G0-R 併入 G1-R,流程瘦身
- **G0-R 擴充**:> 50% → 五問擴充為正式前置段
- **V 檢核不設退場**:零人力成本,永久保留
- 數據來源:報告發現表「可攔截閘門」欄的跨輪統計

## 成長迴路(框架自我機械化)

同型 R 發現在議題帳累計 **≥3 次** → 登錄「候選新 UIV 檢核」,由當值 Trainer 立案評估。
判斷型發現逐步變成機器檢核,人力成本隨使用遞減。

## 範圍外轉介去處

| 面向 | 去處 |
|------|------|
| 無障礙 | 政府無障礙檢測工具軌(如 Freego),獨立於本流程 |
| 前端程式品質 | 開發側 code review(未來 MetaPT 軌) |
| 效能 / SEO | Lighthouse 類套裝工具 |
| SA 規格結構(如拆分觸發) | SA pass 管道轉出,UI 只留痕不處理 |

## UI↔SA 批次通道與回補帳

> 白話:UI 接棒後不逐條同步 SA;僅透過回補帳與版本化交接包進行批次同步。

### 通道一:UI→SA 回補包

- 設計期發現之規格修正建議、DEC-ASM 生效假設、資訊缺口、廢棄建議,一律先登
  **專案側回補帳** `ui/90_Backfill.md`(模板=templates/90_Backfill_template.md);
  設計里程碑一次遞交;跨 repo 遞交走 UI broker。
- 回補包必附「**L2 拓樸差異摘要**」:UI 頁面流與 SA L2 邊拓樸之差異;SA 每批收斂或明示接受分歧。
- 帳目必填欄:ID/類型(修正建議|DEC-ASM|資訊缺口|廢棄建議)/生命週期級/severity/
  來源(報告與 T 問)/影響範圍/建議回補目標/狀態。

### 通道二:SA→UI 交接包更新

- SA 側以版本化交接包(或既有 SA 檔更新+回應對照表)批次回件;
  UI 消費基準錨定=10_UIFlow frontmatter `sa_baseline`(上次消化之 SA 檔版本),
  收件即重生成 00_Digest 對基準看 diff,圈定實際變動面。
- 重跑範圍依下方「回件處理」節縮放表執行(單一權威表)。

### 回件處理(SA→UI;收件到關帳)

> 白話:UI 遞回補包出去、SA 改完檔回件進來,雙方都用**既有載體**,
> 不發明新格式——SA 改自己的檔,UI 更新自己的帳,中間只多一張對照表。

**介面三件套**(沿用既有產出物,只補接軌):

| 方向 | 載體 | 說明 |
|------|------|------|
| UI→SA | `ui/90_Backfill.md` 回補包 | 既有;帳目+L2 拓樸差異摘要,里程碑批次遞交 |
| SA→UI | SA 既有檔更新+**回應對照表** | SA 逐筆回應 BF-###,處置四分類:**採納/替代方案/拒絕附理由/擱置**;回填 90_Backfill「SA 回應對照」節 |
| 消費基準 | 10_UIFlow `sa_baseline`+00_Digest 重生成 | 收件後 diff 圈變動面;消化完成即更新 `sa_baseline` |

**回件重跑縮放表**(依 SA 處置×變動衝擊定 UI 重跑範圍):

| 回件情形 | UI 重跑範圍 |
|---------|------------|
| Clarification(內容替換,結構未動) | 內容替換→UIV 重跑(--gate all)+G2-R 快掃 |
| Contract(欄位/宣告變動,節點未動) | 上列+配置快審重跑(20_FlowPages 步驟 2) |
| 動節點/Breaking | R00 對題審 T0~T5 重跑→四分類(PASS/UI_REORG/ASSUMPTION/BACKFILL)定後續 |
| 拒絕或分歧未收斂 | 失效條款生效(UI 假設不得視為 SA 事實);Breaking 級→該模組 G2 暫緩 |
| 擱置 | 帳目轉休眠(不阻塞閘門);下批遞交自動隨附提醒,任一方可喚醒 |

**BF 狀態機**(補完;90_Backfill 帳目「狀態」欄取值):

```
登帳 →(里程碑)→ 已遞交 → SA 已回應(四分類) → UI 消化(縮放表動作+覆驗) → 關帳
                                └ 擱置 → 休眠(可喚醒)
```

- 關帳條件:對應重跑 UIV 綠+快掃留痕(當輪 R 報告;**無進行中 R 輪時=回補帳「回件處理紀錄」列**)——不自證,與議題四態同紀律。
- 填寫紀律:「SA 回應對照」節**等真回件才回填**,不預填不造假;
  範本見 templates/90_Backfill_template.md v0.2。

### 期中紀律與例外閥

- 期中不逐條跨棒:發現一律假設代決(DEC-ASM)+登帳。
- **例外閥**:🔴 結構性缺口或核心旅程級假設(徵兆:影響三頁以上)且假設代決不可行者,
  得經拍板者核准提前遞交一批。
- **退回例外**:Breaking 級得經拍板者核准退回 SA 側重跑,屬例外路非常態。

### 失效條款與可見性

- SA 對回補未回應者:下一輪同模組不得將 UI 假設視為 SA 事實;
  Breaking 級分歧未收斂→該模組 G2 暫緩。
- **DEC-ASM 可見性**:生效中假設須於 00_Digest 或當輪 R 報告「生效假設」節可見,不得僅存帳。
