# 20|UI flow 與頁面產製(G1 產製)

> 白話:先想清楚使用者的路(旅程),再畫地圖(哪些頁、怎麼走),再畫素描(每頁長什麼樣但不上妝)。
> 每頁「放什麼、不放什麼」先寫成表,畫的時候照表組裝。

## 前置

G0 已 PASS(`ui/reviews/R00_G0.md` 的 gate_result 為準),含對題審段已填(10_SpecReview)。
阻塞 TBD 未裁決不得開畫。

## SA 產出消費規則(UI 端)

- MetaUI 消費 SA 之 L2/L3/L4 時,視其為**資訊庫存與覆蓋率基準**;頁面架構由本檔
  依使用者旅程重組。此規則不改寫 MetaSA 對該等檔案的原始定義。
- **節點/邊二分**:L2 節點及其承載資訊=約束性庫存(UIV-02 勾稽綁定,不得無故漏承載);
  L2 邊拓樸=候選建議,頁面間動線以本檔頁面流為準。
- 重組後判定屬體驗冗餘之 W 節點得不對應頁面:登記表該節點標「捨棄」,
  並登回補帳「廢棄建議」(50_IssueFlow 批次通道)。

## 步驟

### 1. 建 `ui/10_UIFlow.md`(用 templates/10_UIFlow_template.md)

- **導覽主軸**欄必填,引用 00_Glossary 區塊B 的 DEC(如 DEC-NAV-001)。**無 DEC 依據 → 停**,請拍板者先立 DEC。
- **旅程假說**必填(引對題審 T0~T2 證據):使用者帶著什麼來/要完成什麼/第一步要看到什麼/何時算完成。
- **旅程段表**必填:段名/進入條件/離開條件/掛載 US 與 W;每條 US 恰歸一主段(共享須明示)。
  (段名例「發現→評估→取得→整合→維運」屬領域相依示例,不得照抄。)
- 從旅程段導出頁面流程與**頁面登記表**(L2 供覆蓋率勾稽,非頁面清單來源):

| 欄 | 規則 |
|----|------|
| P## | 流水登記,先登記後產檔 |
| 頁面名 | 可中文 |
| 承載 W## | 該頁服務的節點(可多個);捨棄節點標「捨棄(BF-###)」 |
| 主任務 | 此頁唯一主任務,標來源 EP##/W## |
| primary action | 主任務對應的唯一主行動(按鈕/連結字面) |
| 頁面主題 | 一句話;與主任務同源,不與鄰頁重複 |
| 放的資訊 | 引用式填寫(`W##.段名` 指標);單一 W 節點頁得填 `*`(全繼承);禁散文複述規格 |
| 明確不放 | 必填:不放的資訊+去處(頁面 P## / 延後 / 不承載) |
| 首訪路徑 | 首次使用者在此頁看什麼、往哪走(入口級頁面必填) |
| 回訪路徑 | 回訪使用者在此頁的捷徑(入口級頁面必填) |
| 階段 | wire / styled / prototype(產品視圖,見 45_PrototypeView) |
| 檔案路徑 | pages/P##_頁面名.html |

- **強制規則**:主任務、primary action、頁面主題、放的資訊、明確不放=全頁必填;
  首訪/回訪=入口級頁面必填(入口級=自 external 或首頁入邊者、導覽軸根節點);空欄不得開畫(UIV-08 擋主任務/主行動)。
- 一頁只有一個主任務——塞不下就拆頁。
- **配置邊界**:登記表只承擔呈現分配(資訊放哪頁、不放哪頁)。不得新增業務規則、
  改寫資料定義或變更外部流程;配置時發現 SA 事實需修→登回補帳,不在表內改。
- **採納式重組**:對題審全數 PASS 且 SA 拓樸與旅程段一致時,得逕採 L2 拓樸為頁面流,僅補配置各欄。

### 2. 配置快審(AI-R,實例化前)

登記表填妥後、動筆前,對表執行文字層快審:①頁面主題互異 ②「明確不放」之去處可解析
③首訪/回訪欄與旅程假說一致 ④旅程段×US 映射完備(每 US 有主段、每段有頁承載)。
輸出併當輪報告附錄;阻塞項交拍板者。快審通過方得實例化。

### 3. 畫 Mermaid flow

- 節點=P##,邊=操作/條件;每個 P## 一條 `click` 指向 pages/ 實體檔(對齊 L3 互動地圖紀律)
- 外部目的地與暫緩路徑明確標示(external / W99)
- **走通檢核**:每條 BDD Scenario 的 Given→Then 必須能在 flow 上走出一條路;走不通=發現,記入下一輪報告
- 頁面流與 L2 邊拓樸之差異,彙整為「L2 拓樸差異摘要」隨回補包遞交(50_IssueFlow)

### 4. 逐頁實例化(templates/P00_Template.html → `ui/pages/P##_頁面名.html`)

- `<meta pageid/stage/primary-action>` 對齊登記表
- **五態內建**:blank / loading / partial / error / ideal 五個 `data-state` 區塊;不適用者 `data-state-na="狀態" data-reason="理由"`
- 錨定:區塊 `data-w`、術語 `data-term`、連結 `data-nav`、未決內容 `data-tbd` + 佔位樣式
- **連接點徽章**(審查視圖制度元素):頁間連結一律 `data-nav="P##"`(既有型別化紀律),
  樣式須含徽章規則(P00 範本已內建)——`a[data-nav^="P"]:not([aria-current])` 於連結尾端
  顯示 `→P##`、外部連結顯示 `↗外部`,審查時頁對頁的連接點肉眼可辨;
  prototype 產品視圖不帶此規則(45_PrototypeView 規則 2)
- **wire 紀律**:只用範本內建灰階結構樣式;禁品牌色/圓角/陰影/動畫/web font;內容擬真不 lorem
- 每個狀態區塊內**恰一個** `data-action="primary"`
- 版面組裝依「放的資訊」欄列序(列序=版面優先序候選)

### 5. V 檢核、FlowMap 與交審

```
python .metaui/UI_KIT/checks/run_checks.py --gate G1 --scope <F 模組路徑>
python .metaui/UI_KIT/checks/gen_flowmap.py --scope <F 模組路徑> --capture
```

- 修至無 fail → gen_flowmap 產 `ui/00_FlowMap.html`(**縮圖級 storyboard**):
  節點=登記表頁面卡(P## 編號+頁名+主任務+階段+縮圖,點卡開實頁);
  邊=**宣告邊(mermaid)×實掃邊(頁面 data-nav 內容區連結)雙源對照**,
  差異亮標(宣告未實作/實掃未宣告)=審查發現候選;
  全站導覽列與麵包屑屬骨架邊,列計不入對照。
- FlowMap 為 R 層視覺輔件(每輪重生,縮圖非確定性,不入 UIV-06 新鮮度);
  「綜覽頁面串接」自此為 G1-R 固定輸入之一。
- 瀏覽器開啟各頁截圖(五態都截)→ 連同 FlowMap 交 30_ReviewRun 進 G1-R。
