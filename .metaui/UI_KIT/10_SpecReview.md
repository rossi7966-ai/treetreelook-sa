# 10|G0 規格就緒檢核(開畫前)

> 白話:畫面還沒動筆之前，先確認 SA 規格「畫得下去」——缺的決策先要到，
> 省掉畫完才發現地基不穩的重工。這是「先審規格省重工」假設的執行點，
> 攔截數據會回饋門檻(見 50_IssueFlow §門檻)。

## 輸入

- 焦點 F 模組:`F##_L2_Routing.md` / `F##_L3_Workflow.md` / `F##_L4_UserStories.md` / `nodes/*.md` / `F##_REVIEW.md`(TBD 表)
- 全域:`00_Glossary.md`(術語+DEC)、`02_Scope.md`(Epic+RBAC)、`03_Structure.md`

## 步驟

### 1. V 層(機器)

```
python .metaui/UI_KIT/checks/run_checks.py --gate G0 --scope <F 模組路徑> --format text
python .metaui/UI_KIT/checks/gen_digest.py --scope <F 模組路徑>
```

stdout 原文留存，將貼入報告 V 段。fail / parse-error 逐條處置:規格側問題→轉介，輸入缺席→呈報拍板者。

第二行同時生成 `ui/00_Digest.md` **一頁導讀**(生成物，禁手改):模組定位、誰會用、
旅程人話版(W 編號自動翻譯成節點名)、TBD 全表、結構警報——給拍板者的吸收介面，
SA 檔一改重跑即同步。

### 2. R 層五問(逐問記「過/不過+證據」)

| # | 問 | 不過的後果 |
|---|-----|-----------|
| Q1 | W 節點五段完整?§4 元件動態狀態有宣告? | 五態 wireframe 沒有輸入 |
| Q2 | BDD 情境含錯誤/空資料路徑? | Error / Blank 態畫不出來 |
| Q3 | L2 頁面拓樸與 W 節點對齊?有無孤兒頁面/無頁節點? | 頁面清單導不出來 |
| Q4 | RBAC 角色 × 頁面可導出?每個角色在頁面上有落點? | 角色視角缺漏 |
| Q5 | 導覽主軸有 DEC 依據?(如 DEC-NAV-\*) | 主軸無法傳遞，頁面必然搶焦 |

### 2b. 對題審(對題五問;完備性之外檢「題目抓對了沒」)

逐問記 verdict+證據。**證據來源僅規格自身時，verdict 上限=有條件過**。

| # | 問 | 證據方法 |
|---|-----|---------|
| T0 | 主力客群與來訪動機的證據來源為何? | 同域參照(同性質既有站/競品)或拍板者假說欄;僅規格自證=警訊 |
| T1 | 平台第一級實體假說是什麼?規格是否把它作為可瀏覽、可比較、可取得的對象? | 名詞盤點(輔助探針)+L4 US 之 so that 目的段判讀+03_Structure 主體+同域參照→形成候選實體;候選實體僅作為他物屬性=結構性缺口 |
| T2 | 使用者主導動詞類與使命宣告一致嗎? | 由 02_Scope/系統定位宣告預期主導動詞類;L4 動詞盤點(含 so that 段)與宣告不符=警訊，非硬 fail |
| T3 | 最大宗任務的最短路徑幾步? | 以 T1/T2 主任務在 L2 上走一遍，計層深 |
| T4 | 回訪高頻任務有捷徑嗎? | 回訪型 US 對入口層深 |
| T5 | 出口(外部系統/申請/下載)宣告齊備嗎? | L2 外部節點與目的地宣告盤點;「銜接是否順」屬 R 判斷 |

動詞分類字典(最小集):理解類=理解/瀏覽/查看/閱讀;操作類=選擇/比對/設定/操作/申請;
取得類=查詢資料/下載/取得/串接/匯出。

**輸出四分類**(逐 T 記):`PASS` / `UI_REORG`(UI 重組解決，交 20_FlowPages)/
`ASSUMPTION`(假設代決，立 DEC-ASM)/ `BACKFILL`(SA 側資訊缺口，登回補帳)。
不過≠退回 SA:一律先分流上列三處置;退回 SA 重跑=Breaking 級例外(50_IssueFlow 批次通道節)。

### 3. IA 原則對照(接手第一動)

以 `UIFoundation/10_Principles.md` 標【G0 適用】之條目為清單，逐條對照 03_Structure
節點組織、L2 頁面拓樸、導覽軸設計，記 verdict(過/不過)+證據位置，填入 R00 報告
「IA 原則對照」段;不過者列 UIX 發現入議題帳。

### 4. IA 阻塞判定(逐條 TBD 分類，三分)

- **必須先決(阻塞 IA)**:影響頁面數量、導覽結構、主軸者——例:情境分類數量、導覽軸選擇
- **可佔位開畫**:僅影響文案字面、清單內容者——wire 以 `data-tbd` 佔位呈現
- **結構性缺口**:影響第一級實體、主軸、頁面數量、主要旅程、角色路徑或資料取得路徑者——
  記於 R00 對題審段並依四分類處置;**不回寫 F##_REVIEW**(SA 檔唯讀)

輸出「**開畫前決策清單**」節:阻塞 TBD 逐條列給拍板者，附預設假設與影響。

### 5. 產出與過閘

- 報告:`ui/reviews/R00_G0.md`(用 `templates/R00_Review_template.md`)
- **過閘條件**:V 無 fail / parse-error + IA 原則對照段已填 + 對題審段已填(T0~T5 四分類齊) + 阻塞 TBD 全數經 UI 拍板者裁決 → `gate_result: PASS`
- **G1 前置**:R00 報告含已填「IA 原則對照」段;缺席則 G1 不得啟動(UIV 於 G1 子集斷言，fail 即 HOLD)
- F 模組若踩 04_FuncMap 拆分觸發(Epic>3 / 節點>15 / 跨 RBAC 閉環):記入報告「範圍外轉介」,SA pass 管道轉出——不阻 UI 開畫，但必留痕
